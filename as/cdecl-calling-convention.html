1The cdecl frame — one picture to remember

Once the callee has run push ebp; mov ebp,esp, everything has a fixed ebp offset. Positive = caller's stuff (args), negative = mine (locals).

f's frame at f+6, real addresses from gdb ffffc920 [ebp+0x10] 3 c arg 3 ┐ ffffc91c [ebp+0x0c] 2 b arg 2 │ pushed by main (right → left) ffffc918 [ebp+0x08] 1 a arg 1 ┘ ← first arg always at ebp+8 ffffc914 [ebp+0x04] 0x08049192 return address → main+17 (call) ffffc910 [ebp+0x00] 0xffffc928 main's ebp (push ebp) ← ebp ffffc90c [ebp-0x04] 6 s local (sub esp,4) ← esp
  • The 32-bit RE rule of thumb: [ebp+8], [ebp+0xc], [ebp+0x10]… = args 1, 2, 3…; [ebp-4], [ebp-8]… = locals. IDA/Binja name them arg_0, arg_4 / var_4.
  • Args are 4-byte slots, even a char — the stack only does 4-byte pushes in 32-bit mode.
  • Right-to-left pushing is what puts arg 1 at ebp+8 no matter how many args follow — needed for variadic functions like printf (more on reverse order).

2cdecl vs the other 32-bit conventions

Same function a + b + c compiled with gcc's __attribute__((cdecl / stdcall / fastcall)), called with (1, 2, 3):

; ---- call sites (main) ---- push 0x3 push 0x2 push 0x1 call f_cdecl add esp,0xc ; cdecl: CALLER cleans push 0x3 push 0x2 push 0x1 call f_stdcall ; stdcall: nothing here push 0x3 ; only c on the stack mov edx,0x2 ; fastcall: b → edx mov ecx,0x1 ; a → ecx call f_fastcall ; callee cleans
; ---- the callees end differently ---- <f_cdecl>: ... pop ebp ret ; plain ret <f_stdcall>: ... pop ebp ret 0xc ; pop ret addr, THEN esp += 12 <f_fastcall>: sub esp,0x8 mov [ebp-0x4],ecx ; -O0 spills reg args mov [ebp-0x8],edx ... mov eax,[ebp+0x8] ; c is still on the stack leave ret 0x4 ; cleans only the 1 stack arg

Why the caller cleans in cdecl

Only the caller knows how many bytes it pushed. printf("%d\n", r) got 2 args here, but another call site might pass 9. A callee with ret N needs N fixed at compile time — which is why stdcall/fastcall can't do varargs. The price: every call site carries its own add esp,N (slightly bigger code). Bonus: gcc can merge several cleanups into one add, or skip it before leave.

Callee-saved in action

That same main starts with push ebx: it keeps the first result in ebx across the next calls, because cdecl promises ebx survives a call while eax/ecx/edx don't. Since main itself is a callee, it must restore ebx before returning (mov ebx,[ebp-0x4]).

3Modern gcc: the same cdecl, plus 16-byte alignment

The stepper uses -mpreferred-stack-boundary=2 (4-byte alignment, the classic textbook / RE4B look). Without it, today's i386 System V ABI wants esp % 16 == 0 at each call, so gcc adds padding — the convention is the same, only the numbers change:

; classic (stepper) main: push ebp mov ebp,esp sub esp,0x4 ; r push 0x3 push 0x2 push 0x1 call f add esp,0xc ; 3 args mov [ebp-0x4],eax push DWORD PTR [ebp-0x4] push 0x804a008 call printf add esp,0x8 ; 2 args mov eax,0x0 leave ret
; default gcc-13 -m32 main: lea ecx,[esp+0x4] ; realign: main can't trust and esp,0xfffffff0 ; the caller's alignment push DWORD PTR [ecx-0x4] push ebp mov ebp,esp push ecx sub esp,0x14 push 0x3 push 0x2 push 0x1 call f add esp,0xc mov [ebp-0xc],eax sub esp,0x8 ; pad: 8 + 2×4 = 16 push DWORD PTR [ebp-0xc] push 0x804a008 call printf add esp,0x10 ; pad + args ...

takeaways

  • cdecl = all args on the stack, pushed right → left; caller cleans with add esp,N; result in eax.
  • Inside the callee: [ebp+8] = arg 1, [ebp+4] = return address, [ebp] = saved ebp, [ebp-4] = first local.
  • add esp,N after a call tells you the arg count in cdecl: N / 4. A ret N in the callee instead → stdcall/fastcall.
  • eax/ecx/edx can be trashed by any call; ebx/esi/edi/ebp must come back unchanged.
  • Popped args aren't erased — watch printf's args land on the very same slots f's args used (noise in stack).
